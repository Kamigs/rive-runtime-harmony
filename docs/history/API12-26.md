## 优先采用的两项优化

### P1：列表活动状态控制

示例：`har-consumer/entry/src/main/ets/pages/Lifecycle.ets`。`CellPolicy` 汇总激活、可见、页面、Ability 前后台和手动暂停状态。`ActivityRenderer` 继承既有 RiveArtboardRenderer，覆盖 start，拦住 SurfaceChanged 和状态机输入造成的自动唤醒；不清空正在播放的 animation/state-machine 集合。控制器通过现有公开声明路径导入，未扩展 HAR 根导出。

[ComponentActive/Inactive](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/arkts-custom-components-new-lifecycle/) since26.0.0，支持 V1/V2、Stage，初次创建已激活但不发 Active；Inactive 不等同不可见。分别定义 API26 与 legacy 两个 @Reusable 组件，外层先判断 `sdkApiVersion >= 26`，内部使用独立的 `if (deviceInfo.apiAvailable('26.0.0'))`，再判断测试开关选组件；API12不会调用新版本判断函数。`@Available`只参与编译，不是运行保护。复合布尔表达式不被SDK告警分析识别，已改为嵌套分支；Release编译器的API26兼容告警已消除。旧系统仍需实测。

旧系统回退：aboutToReuse/aboutToRecycle（API10）、onVisibleAreaChange（API9）、@Entry 页面及 UIAbility 前后台转发。回收与不可见分别控制，freezeWhenInactive 不是停 native 帧。自动恢复必须保留用户 pause/stop 的语义。样例24项共享同一素材，实际业务复用时还需按 item 更新素材、输入和业务状态。

验证指标：活跃帧持续增长；非激活6秒 settle后 advance 与 native Rive::frame 增量为0；复用是相同instance恢复；手动暂停经过回收后不自动播放；100次快速启停TSFN只创建1次、最终退出释放1次；离屏项停帧而可见项继续；前后台恢复及页面退出无残留帧。A/B 通过 `lifecycleGate=false/true` 在同HAR、同vehicles、同后端比较策略收益。

### 真机压力测试补充：帧回调去重

`ohos_rive/library/src/main/ets/runtime/renderers/Renderer.ets` 的 `scheduleFrame()` 原先每次 start 都 post，stop只停止播放而保留已排队回调；同一vsync内100次stop/start会产生多条回调链。真机1.1.1采样：启停前382次native frame / 384次UI vsync，启停后563 / 326，原生队列上限只能限流，不能消除重复调度。这是已复现的实现缺陷，不归因于API26系统契约变化。

1.1.2用模块私有的ScheduledFrameCallback记录pending：回调触发前只post一次，触发时先清pending再沿用原onFrame，post失败清pending。stop仍持有待触发对象，保留早先快速退出修复；外部自定义framCallBack保持原扩展行为。无新增平台API，API12路径相同；71份声明审计不变。验证比较相同设备/素材/GLES下的native frame/UI vsync比例、100启停后恢复、退出零帧和TSFN创建释放配对。

### P1：中文显式 fallback

示例：`Index.ets::aboutToAppear` 通过现有 `RiveManager.getInstance().setFallbackFont(context, bytes)` 注册 Noto Sans CJK SC，继续原 FontAsset → HBFont → HarfBuzz → Rive fallback → glyph path 链路。字体仅放验收宿主，HAR不增加16MB字体负担。正式工程应按实际字符集、粗细、授权与包体预算选择字体。

[OH_Drawing_FontGetTextPathWithFallback / drawing.Font.getTextPathWithFallback](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/capi-drawing-font-h/) since26.0.0 返回路径，不能直接提供 Rive 所需 HBFont、字体字节和 GlyphRun。因此本轮不接入该系统函数，也不将 ArkGraphics 的新能力写成 Rive 自动支持中文。显式字体方案可沿用API12现有链路，无高版本系统依赖。

素材使用官方 `electrified_button_nested_text.riv`，文本“会员积分奖励”；A/B 每次冷启动清理进程级 fallback 注册，Canvas 与 GLES 分别同后端比较。指标：6个汉字缺字数、字序和可见字形、英文仍正常；记录字体16,437,364字节成本、注册成功与时间，保留字体完整OFL及来源SHA。技术样例通过不覆盖全部CJK码点、粗体、竖排、emoji或MG_Club正式资产。

## 构建和诊断改进

[NativeModuleErrorInfo](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/jscrash-guidelines) 是API26 Release JS Crash新增排错字段，保存最早20条so加载失败；其余查hilog `Load native module failed`。不是新加载器，也不是每次错误都触发crash。旧系统继续收集hilog、加载路径、ABI、DT_NEEDED与HAR/HAP摘要。

[packing_tool](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/packing-tool) 参数表 `--stat-duplicate` since23，针对App/fastApp/multiproject App 输出scan_report；`--deduplicate-so` since26。版本特性表的“新增扫描”口径与参数since不同，采用API参数表。当前独立HAP用本地脚本扫描包内同名/同内容so，正式多HAP APP再用SDK扫描；不自动删除或合并Spine/Rive的libc++。

## 2026-11-10 真机验收结果

Mate70Pro+ / ARM64 / API26 Release 7.0.0.111，本轮SDK26.0.0.105 Release。实际HAR为1.1.2，源码核心1740文件及71份声明核对通过。Canvas/GLES基础、bump、暂停恢复、重建、API26/legacy门控、列表复用、中文冷启动A/B与签名包安装均留证。

- 门控关闭的非激活实例约59.81帧/秒；打开后两后端6秒采样均0帧。最终标签修正后的列表离屏计数1992/2188保持11.176秒，可见项继续增长；6个TSFN全部释放。
